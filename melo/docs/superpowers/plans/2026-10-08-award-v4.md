# Melo V4 Implementation Plan

**Goal:** Evolve the existing product into a music companion with a real catalog, queues, discovery, persistent feedback and a shared character.
**Architecture:** Retain the existing anonymous cloud API, AI emotion contract, Hero and seven expressions. Add a typed local catalog, transparent ranking, on-demand original audio, queue controller and shared music features. Encode catalog IDs alongside legacy mood track IDs for compatibility with the live ECS validation contract.
**Spec:** User brief in attachment 8fffdff9-97cf-4941-915a-476ca782ad4e.
**Execution:** Inline, autonomous per user's explicit instruction; preserve existing deployment until Preview passes.

## Audit
- Current production chain has live real and demo evidence in final-demo-verification.json. Earlier JSON files cover historical Sites releases and do not prove V4.
- Original source README contains obsolete Sites/D1/access/font statements; current production is static Vercel plus proxy to Node/SQLite ECS.
- Audio has five original 90-second buffers. No catalog, source distinction, queue, global player, discovery or Mix.
- Expressions are passed from one hook instance across current UI. No persistent Dock or separate character mode.
- Favorites/history exist; old backend only accepts five mood track IDs. New track IDs must survive transport without collisions.
- Memory snapshots exist but updates alter displayed date; playlist restoration missing. Personality unlocks too early. Today export exists and should be reused.
- New-user Memory/Journey have honest empty states but Listen has only five entries. Extras proactive prompt duplicates proposed Dock and will be removed.
- AI failures preserve input and explicit Demo. Audio is offline-capable after bundle loads. No official TME credentials found in current source/configuration; never infer audio rights from metadata.
